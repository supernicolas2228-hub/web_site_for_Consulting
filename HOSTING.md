# Деплой на VPS / панель (Node.js)

## Что выбрать в конфигурации хостинга

Нужен **Node.js**. Чистый «только PHP», без Node, не подойдёт — это **Next.js** (серверный рендер и API).

Отдельная услуга **PostgreSQL / MySQL** для этого проекта **не обязательна**: события и анкеты хранятся в **файле** `data/site-events.jsonl` в каталоге приложения на сервере.

Версия Node на сервере: **18.17+** (в т.ч. **20/22 LTS**).

**Бесплатный тестовый домен** от хостинга не требует отдельных переменных в коде: Next сам отдаёт ответ на тот `Host`, с которым пришёл запрос.

## Переменные окружения на сервере

Скопируй из `.env.example` и задай в панели хостинга (или в `.env` на VPS):

| Переменная             | Назначение                                                                                                                                 |
|------------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| `NEXT_PUBLIC_SITE_URL` | **Канонический URL сайта** (`https://твойдомен.ru` без слеша в конце). Нужен для Open Graph, редиректа `www`→основной домен и куки админки. |
| `ADMIN_PASSWORD`       | Пароль входа в `/admin`                                                                                                                    |
| `NODE_ENV`             | Обычно панель ставит `production` сама                                                                                                      |
| `PORT`                 | Если хостинг задаёт порт — Next его подхватит                                                                                               |

**Не используются:** `DATABASE_URL`, `DB_CONNECTION_STRING`.

Убедись, что процесс приложения **может создавать и писать папку `data/`** рядом с приложением. Проверка: `GET /api/health` → `database: true` означает «файловое хранилище доступно для записи».

## NetAngels и аналогичные панели

- В панели всё равно задай **`ADMIN_PASSWORD`** для `/admin`.
- Строки подключения к БД из письма хостинга для **этого** приложения задавать не нужно (если только не используешь их для чего-то ещё параллельно).

## Команды (типичная панель «Node»)

1. **Установка:** `npm ci` или `npm install`
2. **Сборка:** `npm run build`
3. **Запуск:** `npm start`  

   (слушает порт из `PORT`, иначе по умолчанию 3000)

`npm run deploy` в `package.json` эквивалентен **`npm run build`** (миграций БД нет).

## Режим standalone

В `next.config.mjs` включён `output: "standalone"`. На VPS можно запускать:

```bash
node .next/standalone/server.js
```

При этом в каталог standalone нужно скопировать `public` и `.next/static` рядом со `server.js` — см. [документацию Next.js](https://nextjs.org/docs/app/building-your-application/deploying#nodejs-server). Проще на старте использовать **`npm start`**.

## Локально без Docker

Достаточно **`.env`** с `ADMIN_PASSWORD` и `NEXT_PUBLIC_SITE_URL`; каталог **`data/`** создастся при первой записи события:

```bash
npm install
npm run dev
```

Docker и `docker-compose.yml` в репозитории — **опционально**, для тех, кто сам поднимает Postgres под другие задачи; приложение к ним не привязано.
