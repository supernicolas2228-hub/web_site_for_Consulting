# Сайт на NetAngels — ссылка и запуск

> **Актуально для текущего кода:** отдельная PostgreSQL приложению не нужна. События и анкеты пишутся в файл **`data/site-events.jsonl`** рядом с Node-процессом. Переменные **`DATABASE_URL`** / **`DB_CONNECTION_STRING`** для этого сайта можно не задавать.

## Готовая ссылка (твой тестовый домен)

- **Сайт (лендинг):** https://sellisgood.na4u.ru/
- **Админка аналитики:** https://sellisgood.na4u.ru/admin

**Пока в панели не выпущен отдельный SSL именно для `sellisgood.na4u.ru`, Chrome может показывать `ERR_CERT_COMMON_NAME_INVALID`:** сервер отдаёт сертификат на `*.netangels.ru`, а браузер ждёт имя **`sellisgood.na4u.ru`** — это не баг сайта, а настройка HTTPS у хостинга.

Что сделать в **NetAngels**: в разделе сайта / SSL / «Защищённое соединение» включить **бесплатный Let's Encrypt** (или свой сертификат) **для домена `sellisgood.na4u.ru`** и дождаться выпуска.

В **`.env` на сервере** в **`NEXT_PUBLIC_SITE_URL`** лучше указать тот адрес, по которому люди реально заходят после настройки SSL, например `https://sellisgood.na4u.ru`.

---

## Переменные окружения в панели (Node.js)

| Ключ | Значение |
|------|----------|
| `NEXT_PUBLIC_SITE_URL` | финальный HTTPS-URL сайта |
| `ADMIN_PASSWORD` | твой пароль для `/admin` |

Строки БД из письма хостинга этому приложению **не требуются**.

## Команды на сервере (порядок важен)

В каталоге с проектом (где `package.json`):

```bash
npm ci
```

(если нет `package-lock.json` — один раз можно `npm install`)

Сборка:

```bash
npm run build
```

Запуск приложения:

```bash
npm start
```

В панели NetAngels в качестве **команды запуска** обычно указывают только **`npm start`** (после того как хотя бы раз выполнили `npm ci` и **`npm run build`**).

Порт: панель часто задаёт **`PORT`** — Next его подхватит.

---

## Локально на ПК (Windows)

Убедись, что в `.env` заданы **`ADMIN_PASSWORD`** и **`NEXT_PUBLIC_SITE_URL`** (для локалки можно `http://127.0.0.1:3030` если `npm run dev` на 3030).

```bash
npm install
npm run dev
```

Папка **`data/`** появится при первой записи события или заявки.

Docker **не обязателен**; `docker-compose.yml` в репозитории — только опциональный Postgres «для себя», приложение к нему не подключается.

Прочее:

- **`npm ci`** иногда падает с **EPERM** на `next-swc...node` — закрой `next dev` / процессы Node, повтори или **`npm install`**.
- **`npm start`** и **EADDRINUSE:3000** — порт занят; останови процесс или:  
  `$env:PORT=3001; npm start` (PowerShell).

---

## Если по ссылке пусто или 502

1. Убедись, что **Node-приложение реально запущено**.
2. Повтори **`npm run build`** после ошибок и снова **`npm start`**.
3. Для режима с API проверь **`GET /api/health`**: должно быть `"database": true` (это про **запись в `data/`**, не про внешнюю БД).

## Локально у себя на ПК

Перед заливкой можно проверить:

```bash
npm run build
npm start
```

Открой http://localhost:3000 (или порт из `PORT`).
